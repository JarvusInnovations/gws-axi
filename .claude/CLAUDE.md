# gws-axi — Claude Code instructions

Agent-ergonomic CLI for Google Workspace (Gmail, Calendar, Docs, Drive, Slides, Sheets, Chat) built to the [AXI standard](https://axi.md). Published on npm as [`gws-axi`](https://www.npmjs.com/package/gws-axi). Source repo owned by JarvusInnovations.

## Commands

| Task | Command |
| --- | --- |
| Install deps | `bun install` |
| Build | `bun run build` (runs `tsc` + `chmod +x dist/bin/gws-axi.js`) |
| Run locally | `bun run dev <args>` (runs TS directly via bun) |
| Run built binary | `node dist/bin/gws-axi.js <args>` |
| Test | `bun run test` |

Tool versions are pinned in `.tool-versions` (bun 1.3.11 / nodejs 22.22.0 via asdf).

**`bun run dev` drops empty-string arguments** (bun's script runner, not the CLI): `--replace ""` arrives as a missing value. To exercise an empty argument use `bun bin/gws-axi.ts <args>` directly or the built `node dist/bin/gws-axi.js`; the published binary runs under Node and is unaffected.

## Architecture at a glance

- **Entry**: `bin/gws-axi.ts` → `src/cli.ts` (uses `runAxiCli` from `axi-sdk-js`)
- **Subcommand handlers**: `src/commands/<service>.ts` dispatcher + `src/commands/<service>/<sub>.ts` per-subcommand handlers
- **Auth**: `src/auth/` — 7-step progressive BYO OAuth setup, OAuth loopback split into prepare + wait phases so agents can relay instructions before callback wait
- **Google API layer**: `src/google/client.ts` (factories), `src/google/tokens.ts` (lifecycle + refresh), `src/google/probe.ts` (doctor probes), `src/google/account.ts` (resolve + write-protection)
- **Output**: `src/output/` — TOON schema builders (`field`, `pluck`, `mapEnum`, `truncated`, etc.) and renderers (`renderList`, `renderListResponse`, `renderObject`, `renderHelp`)
- **Config**: `src/config.ts` — XDG-compliant `~/.config/gws-axi/` with `setup.json`, `config.json` (default_account), `accounts/<email>/{tokens,profile}.json`, `credentials.json`, `setup.html`

## Key design decisions

- **AXI principles**: TOON output, minimal default schemas, contextual `help[]` suggestions, idempotent mutations, structured errors — see `docs/design.md`
- **BYO OAuth client** (single-user, no shared client) — see `docs/shared-client-future.md` for when/if we ship a public shared client
- **Multi-account**: one OAuth client handles many accounts (each added as a test user). Write operations require explicit `--account <email>` when 2+ accounts are authenticated — prevents silent wrong-account mutations. Reads default to `default_account` from `config.json`. Central rule lives in `resolveAccount()` in `src/google/account.ts`.
- **Setup UX**: setup.html is the single browser surface — the CLI never auto-launches browsers (avoids wrong-profile issues). All Google Cloud Console links live on the HTML page, which auto-refreshes every 10s.
- **Auth login default vs split**: `auth login --account X` runs prepare + wait in one command (default — best for humans who can see their own browser). For agent-driven re-auth, pass `--no-wait` on the first call to get fast prepare-only output, relay instructions to the user, then run `auth login --wait` in a SEPARATE bash turn — the wait command binds the callback server and must be listening before the user clicks. Never run the default (blocking) form from an agent context: it'll sit on the callback for up to 5 min while the user can't see what's happening.
- **Remote / phone sign-in** (#69, spec `specs/commands/auth-login.md`): while `--wait` listens (9 min, re-runnable), the callback server also serves the setup page at `http://127.0.0.1:<port>/` — one origin, so one `ssh -L` forward. A prepared sign-in lasts 30 min. When the approving browser can't reach this machine, the user copies the failed `127.0.0.1/callback?…` address and the agent runs `gws-axi auth login --callback-url '<url>'`; under `SSH_CONNECTION` the prepare output adds `auth_url` to hand them. This is the supported path, not a workaround.

## Conventions

- **Fail loud on unknown flags** (`specs/principles.md#fail-loud-on-unknown-flags`, AXI principle 6): every dispatcher entry declares `flags` — a `FlagSpec` checked by `checkFlags` before the handler runs, or `"self"` when the handler parses with `parseArgs` (`src/util/flags.ts`). `auth` declares per subcommand (`AUTH_FLAGS`), `doctor` checks at its top. `flag-declarations.test.ts` fails when a subcommand has no declaration or its declaration disagrees with the flags its `--help` documents — so **a new flag goes in the help text and the declaration together**. `--fields` values go through `parseFieldList`. `axi-sdk-js` does not enforce any of this.

- **Commits**: conventional commits (`type(scope): description`); commit often; stage specific files (never `git add -A`); keep generated-from-command changes in their own commit with the command in the body
- **TypeScript**: strict mode, ESM (`type: module`), Node16 module resolution, target ES2022; avoid bun-specific runtime APIs since consumers run under Node
- **Output**: never leak dependency noise (e.g. `gcloud` stderr) into stdout; all errors are AXI structured (`AxiError` with code + suggestions)
- **--help routing**: for services with real dispatchers (Calendar, Gmail, Docs, Drive, Slides, Sheets, Chat), `<service> <sub> --help` shows subcommand-specific help — requires the service NOT to be in `COMMAND_HELP` in `src/cli.ts`

## Publishing

- **npm**: `gws-axi` unscoped, owners `themightychris` + `jarvus` org, `access: public`
- **Trigger**: creating a GitHub release fires `.github/workflows/publish-npm.yml` which bumps `package.json` to match the tag, builds, and publishes via `npm publish --provenance` (uses OIDC trusted publishing, no `NPM_TOKEN` needed)
- **Flow**: use `/release` slash command — it drafts notes from commits, creates the tag, opens the GitHub release, and CI takes it from there

## Testing approach

- Vitest for unit tests (state mutations, flag parsing, output shape)
- No tests hit real Google APIs in CI — use mocks or recorded fixtures
- Manual E2E for the OAuth flow (can't automate browser consent)
- When adding a service subcommand, test: (1) empty result collapses to `<name>: <human message>` (scalar value under the list's field name — AXI canonical empty-list shape, set in `renderListResponse`); (2) populated result renders default schema; (3) error translation for 401/403/404; (4) account resolution honors write-protection

## Spec-driven development (specops)

This repo uses [specops](https://github.com/JarvusInnovations/specops): **specs are the source of truth; code follows.** Start every feature by updating `specs/`, not by editing code.

- `specs/` — the authoritative desired state. `specs/principles.md` (decisive cross-cutting rules — read these first), `specs/architecture.md` (structure/models), `specs/api/conventions.md` (cross-command contracts), `specs/commands/<service>-<cmd>.md` (per-command). Read the relevant spec before implementing; if it's ambiguous or wrong, fix the spec, don't work around it in code.
- `plans/` — work-in-flight as a micro-DAG (motion, not state). A chunk of work starts with a plan file (`status: planned`), flips to `in-progress`, and the last commit before merge flips it to `done` with `pr:` + checked validation. Protocol: `.agents/skills/specops/references/plans-protocol.md`.
- Plans dashboard: `.agents/skills/specops/scripts/specops` (also `next`, `dag`). A project SessionStart hook in `.claude/settings.json` loads it each session.
- **Spec drift auditing**: run `/audit-spec-drift` to launch the auditor comparing `specs/` against the implementation.
- Spec↔code divergence is a bug, not debt — a PR that changes behavior updates the spec in the same PR.

Uploads replace the file wholesale; there is no way to target one tab/sheet (that needs Docs `batchUpdate` / Sheets `values.update`, i.e. the deferred write surfaces). One flag + one error code cover both (a spreadsheet's sheets *are* its tabs); the container types are registered in `TAB_CONTAINERS` in `src/commands/drive/upload.ts`, with counting helpers in `src/commands/docs/tabs.ts` and `src/commands/sheets/tabs.ts`. - ✅ Docs writes: `create`, `write`, `append` — Markdown into **one tab** through gws-axi's own converter (`src/commands/docs/md-to-doc.ts`; behavior spec `specs/behaviors/markdown-to-doc.md`, command spec `specs/commands/docs-write.md`; plan `plans/docs-markdown-write.md`).
  - **The verb names the converter.** `docs` verbs use ours; `drive upload --convert` stays Google's importer for every source type and never switches by extension. Don't route `.md` uploads through ours, and don't chase parity with Google's output — the target is a **round-trip through `docs read`** (`src/commands/docs/markdown.ts` is the inverse; both share encodings: `Roboto Mono` runs for code, 30pt indents on three sides for a quote, `\u000b` for a hard break, a bottom-bordered empty paragraph for `---`).
  - One `insertText` of the whole body, style requests over computed ranges, then the index-shifting requests (`insertInlineImage`, `createFootnote`, `insertTable`, `createParagraphBullets` — the last removes the nesting tabs it consumed) in **descending index order**. Tables and footnotes are filled in a second batch after a re-read. `writeControl.requiredRevisionId` from the pre-read → `DOCUMENT_CHANGED` on a stale write (observed: 400 "does not match the latest").
  - **Known API gaps, disclosed in `lossy[]` rather than worked around**: no way to set a checked task or create a native code block (Docs stores both — with a language — and Google's importer creates them, but the API neither writes nor returns them, so we write mono paragraphs and open tasks); no alt text on an inserted image; no request that inserts Docs' own horizontal rule. The first paragraph written at the top of a tab gets `spaceAbove: 0` — Google's importer leaves a gap above an opening H1 that the owner removes by hand every time.
  - Tabs by id only (`--tab t.x`), `TAB_REQUIRED` on a multi-tab Doc without one, `--new-tab <title>` adds one. There is deliberately no all-tabs mode here; that is `drive upload --update --replace-all-tabs`, by name.
  - **Space is a paragraph property, never an empty paragraph** (owner's rule; behavior spec § Spacing + local principle; plan `plans/docs-table-writes.md`, #104/#105/#109). The converter removes the empty paragraph `insertTable` creates by deleting the *preceding* paragraph's newline (the stray's own range is a 400; the merge keeps the preceding style), shrinks the one unavoidable stray above a tab-opening table to 1pt, sets `spaceAbove` on the paragraph under a table from the tab's `NORMAL_TEXT.spaceBelow`, and resets every cell's style before filling it (new cells inherit the split paragraph's bold/heading). A table-only body sends no `insertText` (empty text is a 400). `--new-tab` converts before adding the tab and deletes it again on a failed write. `updateNamedStyle` works per tab (mask must include `namedStyleType`) — the lever for house spacing values, not yet used.
- ✅ Tab management (#101; spec `specs/commands/docs-tabs.md`, plan `plans/docs-tabs.md`): `docs write --new-tab` takes placement (`--first|--last|--before|--after|--under`) + `--emoji`; `docs tabs <id>` lists properties only; `docs tabs update <id> <tabId>` (same placement flags + `--top-level`, `--title`, `--emoji`/`--no-emoji`) and `docs tabs delete <id> <tabId> [--with-children]`. Two-word subcommands in the `docs` dispatcher. **Placement arithmetic** (`resolvePlacement` in `src/commands/docs/tabs.ts`): the API's `index` means "insert before the tab currently at this slot in the parent" — `--before X` → `X.index`, `--after X` → `X.index + 1`, `--last` → sibling count *including* the moving tab, no direction adjustment; clearing `parentTabId` un-nests. Nothing upstream reports "unchanged", so idempotence is computed from the pre-read. `deleteTab` takes children silently → `TAB_HAS_CHILDREN` unless `--with-children`; `LAST_TAB` covers the only tab *and* a parent whose subtree is every tab. The four mutable tab properties are `title`, `iconEmoji`, `index`, `parentTabId` — there is no fifth, so no further verb is coming.
  - **Multi-line table cells** (#106; plan `plans/docs-table-cells.md`): a cell's Markdown is split on `<br>` (`parseCell` in `md-to-doc.ts`); plain lines share one paragraph joined by `\u000b`, a line opening with `-`/`1.`/`- [ ]` is its own bulleted paragraph (`createParagraphBullets` works inside a cell at level 0 — **the leading-tab nesting trick does not**, so an indented item is flattened and disclosed as `table_cell_nested_list`). `docs read` joins cell paragraphs with `<br>` and prefixes bulleted ones with their marker, so the issue's example round-trips.
  - **Column-width hints** (#107; plan `plans/docs-table-cols.md`): `<!-- cols: 1 3 -->` or `<!-- cols: 25% 75% -->` on the line before a table → `updateTableColumnProperties` `FIXED_WIDTH` per column, fractions of the tab's content width (`documentStyle` page width minus side margins; 468pt default). Wrong count / no table after it / unreadable → `VALIDATION_ERROR` before any write, never written as text. `docs read` emits the hint back as whole percentages only when columns are fixed and unequal. Chosen over delimiter-dash counts, which formatters normalize away.
  - Google's exporter (`docs download --as text/markdown`) is a secondary check only: it fences code just for its own importer's output, drops bordered rules, and exports every tab at once.
- ✅ Docs `replace-text` (#108 first half; spec `specs/commands/docs-replace-text.md`, plan `plans/docs-replace-text.md`): the API's `replaceAllText` under `tabsCriteria` for one tab, behind a **local match count** — 2+ matches without `--all` is `MULTIPLE_MATCHES` listing each in context; 0 is `action: no_match` exit 0.
