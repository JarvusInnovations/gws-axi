# gws-axi — Claude Code instructions

Agent-ergonomic CLI for Google Workspace (Gmail, Calendar, Docs, Drive, Slides, Sheets, Chat) built to the [AXI standard](https://axi.md). Published on npm as [`gws-axi`](https://www.npmjs.com/package/gws-axi). Source repo owned by JarvusInnovations.

## Commands

| Task | Command |
| --- | --- |
| Install deps | `bun install` |
| Build | `bun run build` (runs `tsc` + `chmod +x dist/bin/gws-axi.js`) |
| Run locally | `bun run dev <args>` (runs TS directly via bun) |
| Run built binary | `node dist/bin/gws-axi.js <args>` |
| Test | `bun run test` |

Tool versions are pinned in `.tool-versions` (bun 1.3.11 / nodejs 22.22.0 via asdf).

**`bun run dev` drops empty-string arguments** (bun's script runner, not the CLI): `--replace ""` arrives as a missing value. To exercise an empty argument use `bun bin/gws-axi.ts <args>` directly or the built `node dist/bin/gws-axi.js`; the published binary runs under Node and is unaffected.

## Architecture at a glance

- **Entry**: `bin/gws-axi.ts` → `src/cli.ts` (uses `runAxiCli` from `axi-sdk-js`)
- **Subcommand handlers**: `src/commands/<service>.ts` dispatcher + `src/commands/<service>/<sub>.ts` per-subcommand handlers
- **Auth**: `src/auth/` — 7-step progressive BYO OAuth setup, OAuth loopback split into prepare + wait phases so agents can relay instructions before callback wait
- **Google API layer**: `src/google/client.ts` (factories), `src/google/tokens.ts` (lifecycle + refresh), `src/google/probe.ts` (doctor probes), `src/google/account.ts` (resolve + write-protection)
- **Output**: `src/output/` — TOON schema builders (`field`, `pluck`, `mapEnum`, `truncated`, etc.) and renderers (`renderList`, `renderListResponse`, `renderObject`, `renderHelp`)
- **Config**: `src/config.ts` — XDG-compliant `~/.config/gws-axi/` with `setup.json`, `config.json` (default_account), `accounts/<email>/{tokens,profile}.json`, `credentials.json`, `setup.html`

## Key design decisions

- **AXI principles**: TOON output, minimal default schemas, contextual `help[]` suggestions, idempotent mutations, structured errors — see `docs/design.md`
- **BYO OAuth client** (single-user, no shared client) — see `docs/shared-client-future.md` for when/if we ship a public shared client
- **Multi-account**: one OAuth client handles many accounts (each added as a test user). Write operations require explicit `--account <email>` when 2+ accounts are authenticated — prevents silent wrong-account mutations. Reads default to `default_account` from `config.json`. Central rule lives in `resolveAccount()` in `src/google/account.ts`.
- **Setup UX**: setup.html is the single browser surface — the CLI never auto-launches browsers (avoids wrong-profile issues). All Google Cloud Console links live on the HTML page, which auto-refreshes every 10s.
- **Auth login default vs split**: `auth login --account X` runs prepare + wait in one command (default — best for humans who can see their own browser). For agent-driven re-auth, pass `--no-wait` on the first call to get fast prepare-only output, relay instructions to the user, then run `auth login --wait` in a SEPARATE bash turn — the wait command binds the callback server and must be listening before the user clicks. Never run the default (blocking) form from an agent context: it'll sit on the callback for up to 5 min while the user can't see what's happening.
- **Remote / phone sign-in** (#69, spec `specs/commands/auth-login.md`): while `--wait` listens (9 min, re-runnable), the callback server also serves the setup page at `http://127.0.0.1:<port>/` — one origin, so one `ssh -L` forward. A prepared sign-in lasts 30 min. When the approving browser can't reach this machine, the user copies the failed `127.0.0.1/callback?…` address and the agent runs `gws-axi auth login --callback-url '<url>'`; under `SSH_CONNECTION` the prepare output adds `auth_url` to hand them. This is the supported path, not a workaround.

## Conventions

- **Fail loud on unknown flags** (`specs/principles.md#fail-loud-on-unknown-flags`, AXI principle 6): every dispatcher entry declares `flags` — a `FlagSpec` checked by `checkFlags` before the handler runs, or `"self"` when the handler parses with `parseArgs` (`src/util/flags.ts`). `auth` declares per subcommand (`AUTH_FLAGS`), `doctor` checks at its top. `flag-declarations.test.ts` fails when a subcommand has no declaration or its declaration disagrees with the flags its `--help` documents — so **a new flag goes in the help text and the declaration together**. `--fields` values go through `parseFieldList`. `axi-sdk-js` does not enforce any of this.

- **Export files** (`specs/api/conventions.md` § Export files; `src/util/export.ts`): a command whose result can outrun its cap offers `--json-out[=<path>]` / `--csv-out[=<path>]` — the rendered rows never change (whole-payload counts may become exact), the response adds `wrote:`, `columns:` and a `jq`/`head` line; bare = `<tmp>/gws-axi-<uid>/<UTC stamp>-<kind>.<ext>` at `0600` — **owner-only by construction**: the dir is `lstat`-checked (real dir, our uid, no group/other bits, else `EXPORT_WRITE_FAILED`) and files are created `wx` (O_EXCL, `-2`/`-3` on a collision), because a shared `/tmp` lets another user pre-create the dir with symlinks at the predictable names; an explicit path that replaced a file says `overwrote`; one per call; a failed write renders `export_error` beside the preview and exits 1. These are the only **optional-value flags**: declared in `FlagSpec.optional`, value only with `=` (`--csv-out=./x.csv`); `=` on a value flag (`--range=B2`) is a usage error; `--<declared flag>=…` after a value flag is never taken as its value; `--csv-out out.csv` is refused with the `=` form via `extraArgumentError`. Offered by `sheets read` (whole tab) and `sheets query`.
- **Commits**: conventional commits (`type(scope): description`); commit often; stage specific files (never `git add -A`); keep generated-from-command changes in their own commit with the command in the body
- **TypeScript**: strict mode, ESM (`type: module`), Node16 module resolution, target ES2022; avoid bun-specific runtime APIs since consumers run under Node
- **Output**: never leak dependency noise (e.g. `gcloud` stderr) into stdout; all errors are AXI structured (`AxiError` with code + suggestions)
- **--help routing**: for services with real dispatchers (Calendar, Gmail, Docs, Drive, Slides, Sheets, Chat), `<service> <sub> --help` shows subcommand-specific help — requires the service NOT to be in `COMMAND_HELP` in `src/cli.ts`

## Testing approach

- Vitest for unit tests (state mutations, flag parsing, output shape)
- No tests hit real Google APIs in CI — use mocks or recorded fixtures
- Manual E2E for the OAuth flow (can't automate browser consent)
- When adding a service subcommand, test: (1) empty result collapses to `<name>: <human message>` (scalar value under the list's field name — AXI canonical empty-list shape, set in `renderListResponse`); (2) populated result renders default schema; (3) error translation for 401/403/404; (4) account resolution honors write-protection

## Spec-driven development (specops)

This repo uses [specops](https://github.com/JarvusInnovations/specops): **specs are the source of truth; code follows.** Start every feature by updating `specs/`, not by editing code.

- `specs/` — the authoritative desired state. `specs/principles.md` (decisive cross-cutting rules — read these first), `specs/architecture.md` (structure/models), `specs/api/conventions.md` (cross-command contracts), `specs/commands/<service>-<cmd>.md` (per-command). Read the relevant spec before implementing; if it's ambiguous or wrong, fix the spec, don't work around it in code.
- `plans/` — work-in-flight as a micro-DAG (motion, not state). A chunk of work starts with a plan file (`status: planned`), flips to `in-progress`, and the last commit before merge flips it to `done` with `pr:` + checked validation. Protocol: `.agents/skills/specops/references/plans-protocol.md`.
- Plans dashboard: `.agents/skills/specops/scripts/specops` (also `next`, `dag`). A project SessionStart hook in `.claude/settings.json` loads it each session.
- **Spec drift auditing**: run `/audit-spec-drift` to launch the auditor comparing `specs/` against the implementation.
- Spec↔code divergence is a bug, not debt — a PR that changes behavior updates the spec in the same PR.

- ✅ Sheets writes: `update`, `append`, `clear`, `create`, `add-tab` (spec `specs/commands/sheets-write.md`, plan `plans/sheets-write.md`). **Values only**: the requests sent are the values call, a grid growth when the block wouldn't fit, and the `--header` freeze. Value block = CSV (own RFC 4180 reader, `src/commands/sheets/values.ts`), TSV, or `--json` 2-D array (`null` skips a cell, `""` clears); `USER_ENTERED` unless `--raw`; source rule shared with `docs` via `src/util/source.ts`.
  - **Every write reads back** (`writePlan` in `src/commands/sheets/write.ts`): `formulas[]` (every formula written, result or error + Sheets' message), `written[]` (previous value = the undo; display ≠ input = the proof), and the **tab-wide formula-error diff** (`errors[]` new-or-written, `errors_fixed`, `errors_elsewhere`) from an errors-only mask fetched beside the pre-read and the read-back (separate parallel request — one fields mask per call). Exit 0 with errors. The mask is **not compact** (~22 B per populated cell: 585 KB at 1000×26, 4.5 MB/~610 ms at 200k), so above 200,000 allocated cells the scan covers the written range and says `error_scan:`.
  - **Upstream facts the code rests on (observed 2026-10-24)**: `values.update` grows the grid itself only for a block spilling from an anchor *inside* it — a range/anchor outside is refused, so `writePlan` grows first — with **`appendDimension`, relative to the read**, never an absolute `rowCount` (a stale absolute count deletes rows a concurrent append added); a tab title standing alone as a range is **always quoted** (`quoteTitle`) — bare `Q4` is cell Q4 of the first sheet; titles are unique **case-insensitively**, chart sheets included; the `unchanged` shortcuts honor `properties.locale` and `TEXT` cells; a protected range is a **400** "protected cell or object", not a 403; `1/2` becomes a date that still *displays* `1/2`, so `written[]` annotates `1/2 (date 2026-01-02)`; `values.append` starts rows at the **last data block's first column** (not always A), so header-keyed `append` rows go through `writePlan` at column A after the last row with data in the header's columns, while plain rows keep `values.append`.
  - The pre-write comparison (`storesSame` in `compare.ts`) errs toward "changed" for any `USER_ENTERED` string Sheets might parse; `action: unchanged` sends nothing. `create` goes through Drive `files.create` (so `--parent` works), then `batchUpdate` renames/adds tabs; failures after the file exists are `WRITE_INCOMPLETE` naming the id. `add-tab` is idempotent by title (`exists`) and deletes the tab again when its seed fails (`rollBack`).
  - **Keyed update** (`update --json [--key <header>] [--append-missing]`; `src/commands/sheets/keyed.ts`, plan `plans/sheets-keyed-update.md`): JSON objects edit **existing** rows found by the key column's *displayed* text (trimmed, case-sensitive, below row 1; a `0000`-formatted `1` matches `"0001"`, not `1`). Objects with neither `--range` nor `--cell` are keyed on **column A's header** by default. The whole block is checked before any call — `ROW_NOT_FOUND`, `ROW_AMBIGUOUS` (row numbers), duplicate key, missing key. A **near miss** (case only, or a number shown formatted: `7.00`, `$1,200`, `0001`) is `ROW_NOT_FOUND` even under `--append-missing`, which would otherwise add a duplicate. The pre-read reads one rect per row and re-checks each matched row's key cell → `ROW_MOVED` when a sort/insert moved it; `range:` is the bounding rect `(N rows)`. The write is a `{kind:"cells"}` plan through `writePlan` (the `--cell` path); `--append-missing` rows are placed by the keyed-append rule and ride the **same** `values.batchUpdate` after the matched cells, so one report covers both. `rows[N]{key,row,cells,action}` (`updated`/`unchanged`/`appended`) comes from `WriteOutcome.changedCells`.
- ✅ Sheets `note <id> <A1> (--text | --clear)` (spec `specs/commands/sheets-note.md`, plan `plans/sheets-note.md`; `src/commands/sheets/note.ts`): one cell's note through one `updateCells` under the `note` mask — value and number format untouched (observed). **`--clear` sends the cell with no `note` under the mask**; `note: ""` clears too, and both leave no `note` key. Idempotent from a pre-read (`planNote`); `note{before,after}` + an undo line (`$'…'` quoting when the note has newlines — a help line can't hold one; over 2,000 characters it becomes a `drive revisions` pointer instead). A note starting with `--` works: `parseArgs` only treats a flag-shaped token (`/^--[A-Za-z][A-Za-z0-9-]*$/`) after a value flag as a missing value. Empty `--text` is refused toward `--clear`, a range is `VALIDATION_ERROR`, a cell outside the tab's grid is `RANGE_INVALID` (local check). No length limit hit at 2,000,000 characters, so no local cap. A protected cell is the same 400 → `PROTECTED_RANGE` as the value writers.
- ✅ Sheets tab management: `tabs`, `tabs update`, `tabs delete` (spec `specs/commands/sheets-tabs.md`, plan `plans/sheets-tabs.md`; `src/commands/sheets/tabs.ts`, which still exports `listSpreadsheetSheets` for `drive upload`). Two-word subcommands in the `sheets` dispatcher, as in `docs`. Lists **every** sheet — `tabs[N]{gid,title,index,kind,hidden,frozen_rows,frozen_cols}` — from its own `fetchSheets` (chart sheets included; `fetchMeta` stays grid-only). **Chart sheets are `sheetType: OBJECT`** upstream (not `CHART`) → `kind: chart`.
  - **update**: one `updateSheetProperties`, mask = only the properties that differ from the pre-read (`diffTabProps`); nothing differs → `action: unchanged`, nothing sent. **Placement** (`resolveTabPlacement`) uses before-the-move indices, observed: `--first` 0, `--last` the sheet count, `--before X` X.index, `--after X` X.index+1; a sheet sent its own index or index+1 stays put. Refused locally: a title another sheet holds case-insensitively (its *own* title in another case is a rename, accepted upstream), a freeze ≥ the allocation, any freeze on a chart sheet, hiding the last visible sheet (`LAST_VISIBLE_TAB`; **chart sheets count as visible**). Undo line from the pre-read: `--after <previous predecessor>` or `--first`, plus the old title/visibility/freezes.
  - **delete**: `values.get` populated-cell count (`cells`), then an errors-only `spreadsheets.get` of the **whole spreadsheet** (no `ranges`, `properties.title` in the mask so cells are tab-qualified) before and after, diffed with `diffErrors`; the deleted tab is left out of the before-map. Fix lines are `fixLines` per error with the cell re-qualified; the formula text keeps the dead sheet name (`=Archive!B2`). Skipped past 200,000 allocated cells (`error_scan: skipped (spreadsheet is N cells)`). Measured: ~199k allocated / 76k populated → 1.8 MB, 0.3–0.6 s. `LAST_TAB` for the only sheet; **upstream also refuses deleting the only visible sheet** while others are hidden → `LAST_VISIBLE_TAB`.
  - **A title spelled as digits can shadow a gid** (title-first resolution): `tabs update`/`delete` refuse a selector that is one sheet's title and another's gid (`ambiguousSelector`), and generated commands address a sheet through `sheetRef` (gid, or title when some title spells it). Delete errors carry `title`/`a1` from the scan — never re-parse a qualified cell (a `'!` title breaks `splitQualifiedRange`).
